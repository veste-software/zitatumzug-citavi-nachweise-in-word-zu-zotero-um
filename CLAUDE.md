# Zitatumzug: Citavi-Nachweise in Word zu Zotero umwandeln

Built by an automated studio. Read `SPEC.md` (what and why), `PLAN.md` (the task list) and this file (how) before changing anything.

## Rules for every contributor, human or agent

- Never commit secrets. Environment variable names go in `.env.example`, values never do.
- Payments stay in test mode until the owner goes live.
- Do not run `git commit` or `git push`. The studio orchestrator commits.
- `npm test` and `npm run build` must pass before work counts as done.
- Pages that answer a search query must be real tools or substantive answers, never thin filler.

## Stack, layout and commands

### Stack

- **Astro 5** (static output, TypeScript strict) with **Preact** islands for the tool UI. `@astrojs/sitemap`.
- **No Tailwind** (deliberate deviation): the hand-built ledger/price-tag design lives in one stylesheet of CSS custom properties, `src/styles/global.css`. Do not add Tailwind, a UI kit or an icon pack.
- Fonts self-hosted via `@fontsource/zilla-slab` (display) and `@fontsource-variable/source-serif-4` (text). See `DESIGN.md` – read it before touching any markup or CSS.
- Zip: `fflate`. XML: the browser's `DOMParser`/`XMLSerializer`; in tests `@xmldom/xmldom`. The core receives the parser by injection.
- Tests: **Vitest** (`vitest run`, Node environment).
- Hosting target: **Cloudflare Pages** (static `dist/` + Pages Functions in `functions/`). Previews: GitHub Pages under `/<repo>/` (functions do not run there; the UI must degrade to "Bezahlung ist gerade nicht verfügbar").

### Layout

```
src/
  core/          pure conversion core (no DOM globals, no network) – scan, decode, map to CSL, write fields, export RIS/CSL-JSON
  lib/           browser helpers: url.ts (href() for base path), token verify, event counter, zotero linking
  components/    Astro components (Tag.astro = signature hang tag) and Preact islands (*.tsx)
  layouts/Base.astro   html shell, header, footer (legal links + non-affiliation note), analytics beacon
  pages/         one file per route; robots.txt.ts
  styles/global.css    ALL design tokens and base styles
functions/api/   Cloudflare Pages Functions: checkout.ts, verify.ts, event.ts (+ shared logic in functions/_lib/)
public/          favicon.svg, _headers (production CSP)
scripts/         design-check.mjs (studio-owned, do not edit), js-size.mjs, make-fixtures.mjs
tests/           *.test.ts; tests/fixtures/ synthetic .docx generated by scripts/make-fixtures.mjs
fixtures/real/   real Citavi documents (gitignored, human-provided); tests skip with "SKIPPED: no real Citavi fixtures"
```

### Commands

| Command | What |
|---|---|
| `npm run build` | static build to `dist/` |
| `npm run build:preview` | same build with `SITE_URL=https://example.github.io SITE_BASE=/preview` – every link must start with `/preview/` |
| `npm test` | Vitest, runs once |
| `npm run lint` | `astro check` (types for .astro/.ts) |
| `npm run design-check` | studio check for AI-looking design habits; must exit 0 |
| `npm run size` | gzip size of JS in `dist/` (after build); `-- --max-kb=N` to enforce |
| `npm run fixtures` | regenerate synthetic fixtures (script written by the Builder) |

### Conventions

- Every internal link/asset goes through `href()` from `src/lib/url.ts` (respects `SITE_BASE`). Never hard-code `/something`.
- UI copy is German, „Sie“-form, plain; see the voice section in `DESIGN.md`. Proper „…“ quotes and – dashes.
- `src/core/**` must never contain `fetch`, `XMLHttpRequest` or `sendBeacon` (a test enforces this). The Zotero API key never goes to storage or any host other than `api.zotero.org`.
- Do not copy code from CiteMigrate (GPL-3.0) or biblatex-csl-converter; implement from the format facts in SPEC §3.
- Functions take their dependencies (Stripe fetch, signing key, env) as parameters so tests can mock them; no Stripe SDK – call the REST API with `fetch`.
- Env var names live in `.env.example`. Public (browser) vars start with `PUBLIC_`.
- Every page uses `layouts/Base.astro` with a unique `title` and `description` and exactly one `<h1>`.
